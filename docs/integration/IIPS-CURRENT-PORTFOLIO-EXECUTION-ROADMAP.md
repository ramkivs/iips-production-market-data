## Operating conventions and counting

- Work-item IDs **W01–W20** are stable. Each is a distinct closure outcome; entries may contain parallel tasks, but an implementation is separated from its governing decision where independent acceptance matters.
- Status flags in the index are **overlapping**, not mutually exclusive. **Now** means the specifically stated read-only portion may start under this request, not that the entire item can close. **G** = awaiting governance, **E** = awaiting external access/evidence, **I** = some implementation requires separate authorization. A dash means the flag is not asserted for that item; every downstream item still needs its listed predecessors and independent verifier. None of the implementation items is execution-ready today.
- Decision accountability is **unassigned** unless explicitly stated. Execution roles are **proposed**, not assigned commitments. Each item needs an **independent verifier, currently unassigned**; no named team below is silently promoted to independent acceptance authority. The IID single-user operator has documented policy/evidence authority **only within the IID scope recorded in audit L**. IPD owns provider qualification/freshness semantics and portfolio service; IRR owns its consumer/analytical/report contracts. Host access belongs to the host owner. These established boundaries do not designate a cross-product accountable owner.
- Authorization in each item is a future gate; this task authorizes only read-only investigation and documentation. In particular synthetic test execution or generating/versioning real artifacts needs separate permission when it entails test mutations or user data. All host inspection, even read-only, additionally requires the host owner's permission and controlled access. Never disclose sensitive observations in published evidence.
- An item closes only after its deliverable, acceptance criteria **and** evidence are independently reviewed by a designated verifier; unresolved ownership is itself a blocker. Evidence packages should carry immutable revision/digest, environment, time, scope, decision and redacted results. Negative decisions must explicitly define retained reference/unavailable behavior and downstream consequences, not be treated as approval to implement current analytics.
