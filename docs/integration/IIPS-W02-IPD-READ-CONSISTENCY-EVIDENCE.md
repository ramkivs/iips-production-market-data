# W02 — IPD synthetic read-consistency evidence

Scope: synthetic temporary SQLite databases only. This is IPD's test and correction, not IRR consumer implementation or real-portfolio evidence.

## Contract and controlled interleavings

- Each `portfolio.get`, v2 detail and `portfolio.revisions` projection uses a single SQLite read snapshot. Holdings and the current contribution ledger returned by a detail call reflect the same database snapshot. The contribution ledger is not a historical, per-revision ledger. When a caller already has a transaction, the read uses it without taking ownership.
- Each list, detail, and history request is a separate observation; different calls can legitimately return different revisions. A consumer capturing a single revision must compare revision evidence and recapture on mismatch. Independently timed quote source, receipt and evaluation times remain separate observations; no portfolio/quote cross-service atomicity is asserted.
- IPC resolves one active binding and membership per request, serialized against a competing binding writer. Multiple active rows, missing membership, or a membership attached to a different binding fail closed. V2 additionally requires the authorized holdings owner/tenant. Once resolved, the owner for an in-flight request is pinned; a binding switch after resolution affects the next request, not the already-resolved request. Missing, foreign and tombstoned resources remain indistinguishable on the wire.
- In WAL fixture tests, a test-only proxy pauses after a real read statement and synchronously invokes a second connection's transaction before the next read. The test asserts the barrier order and results. A reset between holdings and contributions originally produced old holdings and the new ledger; the snapshot correction returns the old holdings and old ledger while the writer commits the next revision. Another barrier switches bindings and resets the portfolio during the in-flight detail read. A competing binding replacement during `BEGIN IMMEDIATE` cannot commit until binding resolution ends; the test asserts the failed attempt, rollback and successful subsequent replacement. Tests also cover malformed multi-active fixture states and the real single-active uniqueness indexes.
- With the production-configured rollback journal, the corresponding writer cannot commit through an active reader in the controlled interleaving. The tests also cover list/detail/history revision changes, tombstone, reset, retained historical holdings, cap, independent freshness evaluations, transaction cleanup and caller-owned transaction preservation. These deterministic interleavings do not prove all possible schedules or cross-process deployments.

Reproduce with the project's TypeScript test runner (for example `npx tsx --test tests/stage2_binding_concurrency.test.ts tests/stage2_portfolio_read_snapshot.test.ts`) and the existing IPC read-contract/isolation and freshness regressions. W09 remains IRR-owned and must implement and verify its own mismatch handling; W03 actual inventory and W04–W06 actual data/rights evidence remain separate dependencies. No real data, production, or IRR changes were involved.
