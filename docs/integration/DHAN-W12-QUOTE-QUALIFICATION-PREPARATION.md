## Request-attempt boundary and limitations

The explicit quote route validates the canonical identity, resolves the exact mapping, and passes through the coalescer, rate limiter and concurrency limiter before provider access. The client resolves credentials and uses `DhanServerHttpsTransport`, which enforces non-production, HTTPS/origin pinning, TLS checks, timeout and redirect refusal. Previously the orchestrator called `withBoundedRetry` (default three total attempts) for transient quote failures. Quote refresh now makes **at most one** provider fetch per orchestrated execution, including 429, 5xx, transport errors and timeouts. The reusable retry helper is unchanged for other users; quote calls no longer invoke it. Tests count one mocked HTTPS `fetch` invocation through the authenticated HTTP/service/egress path for success and representative failures, with redirects disabled, and verify unauthorized local requests make zero invocations. No credential or transport guard is bypassed.

This is an **application-level at-most-one-attempt** control, not a promise that every request reaches Dhan: validation, credentials, limits or security guards may prevent all egress; coalescing may share an in-flight request; a timeout may occur after the vendor received it. Multiple client submissions, browser refreshes, caller-side retries, separate processes, proxy/runtime behavior and network delivery are outside this single invocation's control. A failed or timed-out request must not be repeated automatically. Actual deployed Windows code and runtime have not been inspected or changed; this candidate must be reviewed, installed by the owner and verified before relying on the control. Do not claim a physical vendor receipt or an exactly-once distributed guarantee from mocks.
