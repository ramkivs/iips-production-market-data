# Stage 4 broker-import IPC integration

`startIpcServer` constructs the existing `createBrokerImportConsumer` with the governed P04/P7 dependencies and a server-owned authorization context, and injects that exact consumer into the existing same-host IPC dispatcher. No new persistence implementation or HTTP route is introduced. The v1 operation is `portfolio.importBroker`; v2 remains unchanged. It uses the existing length-prefixed, one-request-per-connection IPC protocol and its caps and settlement policy.

The payload is the existing `BrokerImportRequest`: `portfolioId`, `expectedRevision`, raw broker-observed `holdings`, `contentDigest`, `fileName`, `sourceBroker`, `importedAt` and optional `mode`. The request admits no owner or authority claims, canonical company identity, or extra fields; invalid structures are refused. The dispatcher resolves the active local binding itself on every request and checks the existing write guard before calling the injected consumer, whose durable port independently verifies its server-owned context. Missing or invalid binding and caller-supplied authority remain zero-byte Class P refusals. Default-deny `WRITE_NOT_AUTHORIZED` is a Class A response. An absent consumer is `UNAVAILABLE`; unexpected errors are sanitized `UNAVAILABLE`. No owner is supplied by the IPC caller.

A normal response has `{v:1, ok:true, op:'portfolio.importBroker', requestId?, result: BrokerImportOutcome}`. Outer `ok:true` means only that dispatch returned; **inspect `result.ok`**: `true` is the actual persisted success receipt with `revision`, `holdingsPersisted`, disposition and store effect; `false` is the unchanged structured consumer refusal including `code`, `storeEffect` and refused holdings; `'unknown'` is the existing lost-acknowledgement outcome and is not a success or permission to retry. Protocol/authorization failures use the existing `{v,ok:false,op,requestId?,outcome,detail?}` Class A envelope; Class P sends no response. Duplicate submissions follow the existing idempotency contract, including its existing receipt fields.

`BrokerImportIpcRequest`, `BrokerImportIpcResponse`, and the original broker-import payload/result types are exported as **types only** through `./portfolio-ui`. This is an IPC vocabulary, not a browser-accessible IPC implementation, owner context, transport, durable store or write authorization. The server implementation and Node internals remain outside the browser closure. Consumer adoption, deployment and browser acceptance are separate work.
