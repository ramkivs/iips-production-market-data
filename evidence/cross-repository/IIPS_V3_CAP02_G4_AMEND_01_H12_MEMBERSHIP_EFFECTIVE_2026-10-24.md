## 1. What this amendment decides, and what it deliberately does not

**It decides**, on the Program Authority's express selection of Alternative A:

1. that the effective Gate 4 Act §8 mandatory **IPD core count is `32`**, not `33`;
2. that the `32` is the original D-7 mandatory set, `entries[0..31]`, **which already contains**
   `tests/g4_run_tests_summary_parsing.test.ts` at `entries[23]`, so that the parser test is **not** an additional
   thirty-third path;
3. that `scripts/test-summary-parser.mjs` remains **one separate conditional helper** and is **not** promoted into
   the mandatory core;
4. that the mandatory IRR consumer set remains **`24` paths**, so the **total mandatory core manifest is `56`
   entries** (`32` IPD + `24` IRR);
5. that the **seven** additional post-G3 CAP-02 qualified-surface paths remain in the separate
   `post_g3_cap02_qualified_surface_entries` set and are **not** collapsed into the `32`-path original core and are
   **not** added as new `entries`;
6. that the independent verification requirement for all **`1,140`** compiled `dist/**` artifacts is **preserved**
   and is **not** reinterpreted as additional source paths;
7. that the stale `.github/workflows/ci.yml` parenthetical in §8 is corrected to the verified authorized blob
   `4614ee0e27fe8a8f0b4f4883bacc141e2d67aae5`;
8. that Alternatives **B** and **C** are **not** selected, **not** adopted and confer **no** authority.

**It does not decide and does not authorize:** Gate 4 qualification execution; execution of QE-1…QE-11; H-12
adoption (R1 and R2 remain candidates); Gate A′ provisioning; selection or fabrication of `principal_label`,
`tenantId` or `canonicalOwnerId`; U4 result acceptance; Gate C acceptance; Gate 5 admission; any U6/W-1 operational
write authorization; any change to `SESSION_ONLY` / `durable:false` behaviour; any IRR mutation; any source, test,
package, build-script or CI-workflow change; any promotion of an off-`main` lineage; and any modification of the
amended file itself.

## 4. The erroneous `33` and the verified basis for `32`

### 4.1 How `33` arose

The amended act's own parenthetical states its derivation: *"the candidate's 32 + the mandatory parser test"*.
That operation is a double-count, because the candidate's `32` **already contains** the parser test.

### 4.2 The authoritative source of the `32` — IRR `D-7` §4.7 (blob `7d3b143e…`)

`docs/integration/IIPS_v3.0_G4_DETERMINATION_RESOLUTION_PACKET_D1_TO_D12_2026-10-22.md`, §4.7, states the proposed
membership verbatim as:

> **"32 mandatory IPD paths"** = rev-2's **27** (4 `src/ipc/*` + 10 `src/persistence/*` + 8 `tests/g3_*` +
> `scripts/run-tests.mjs` + **`tests/g4_run_tests_summary_parsing.test.ts`** + `package.json` + `package-lock.json`
> + `tsconfig.json`) **+ 5** (`src/identity/security_master.ts`, `src/identity/mapping_store.ts`,
> `src/identity/quarantine.ts`, `frontend/src/features/portfolio/portfolioStorePort.ts`,
> `frontend/src/features/portfolio/portfolio-store.ts`),

with **`+1 conditional`: `scripts/test-summary-parser.mjs`**, and with the adoption gate stating *"The current
candidate has 31 of 32 mandatory IPD paths present; required `tests/g4_run_tests_summary_parsing.test.ts` is absent
at the accepted baseline."* The parser test is therefore **inside** the `32`, in the authoritative design record,
from the outset.

### 4.3 The reconciled candidate's own array proves the same point

`G4-H12-MANIFEST-v3-CANDIDATE-2026-10-23-R2` carries `entries` of length **`56`**: `32` IPD records at
`entries[0..31]` and `24` IRR records at `entries[32..55]`. `entries[23]` **is**
`tests/g4_run_tests_summary_parsing.test.ts`, state `PRESENT`, blob `49e901b6ca957a5cc705b42e96cdeaf0365cfbc9`,
raw SHA-256 `7907087f13053e232e1ae537d6b75de5f5b280728ce9af1e210041c4660b633d`, `5,627` B. Its predecessor `v2`
(`docs/integration/G4-H12-MANIFEST-v2-CANDIDATE-2026-10-22.json`, IRR blob
`3b64c4ac4ae31d4c318b3de7183874a27c178eef`, raw SHA-256
`3eedd70c994271dfc9ac23bd603f7a9e2f273cb1a68d3172cd3a7737344096ae`, `115,308` B) already carried the same
path at the same index with state `ABSENT_AT_PINNED_BASELINE` — `31 PRESENT + 1 ABSENT = 32`.

### 4.4 Set arithmetic

`| entries_v2_IPD ∪ { tests/g4_run_tests_summary_parsing.test.ts } | = 32`, because the added element is already a
member. `32 + 1 = 33` is therefore not a set-union cardinality of anything; it is a sum of a cardinality and one of
its own members.
